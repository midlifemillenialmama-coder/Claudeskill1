# Weekly Brief

Produce a one-page brief the user can read in two minutes. Read only. Never send, reply to, label, delete, or share anything.

## Before starting

1. Check which of Google Calendar, Gmail, and Google Drive are connected. Work with what is available. If none are, tell the user to connect them in Cowork settings and stop.
2. If `references/preferences.md` has been filled in by the user, apply it (priority people, ignored senders, working hours). Otherwise use defaults.
3. Pick the window: this week (Monday to Sunday) when run Friday through Monday, otherwise the next 7 days. State the dates at the top of the brief.

## Gather

- **Calendar:** list events in the window. Note back-to-back stretches, days with no free block over 90 minutes, double bookings, and events with no description or agenda.
- **Gmail:** search threads from the last 7 days that
  - ask the user a question or request something and have no reply from the user, and
  - the user sent that got no answer after 3 or more days.
  Skip newsletters, receipts, and automated notifications unless they contain a deadline.
- **Drive:** list files the user edited or that were shared with them in the last 7 days. Include only those tied to a meeting or request found above.

## Write the brief

Use this order. Omit any section that is empty.

1. **The week in one line:** the shape of the week (for example, "Heavy Tuesday and Thursday, open Wednesday afternoon").
2. **Needs a decision or reply this week:** up to 7 items, most urgent first. Each item: who, what they want, how long it has waited, and a suggested next step.
3. **Waiting on others:** messages the user sent that went unanswered. Include the date sent.
4. **Calendar:** one line per day with the meetings that matter, plus conflicts and meetings that need prep. Link prep documents from Drive when found.
5. **Suggested time blocks:** up to 3 open slots for the top items above.

## Rules

- Quote dates and names exactly as found. Never invent a meeting, sender, or deadline. If a search returned nothing, say so.
- Keep each item to one or two lines. No preamble, no closing summary.
- If a connector call fails, name which source is missing at the top of the brief and continue with the rest.
- Offer drafts of replies after the brief, only when the user asks. Create drafts, never send.
